# termtab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A free Chrome new-tab extension: a macOS desktop with a menu bar, a greeting/focus line, a search window and user-chosen widgets, each drawn as a macOS Terminal window, reorderable by drag, with no install warnings.

**Architecture:** Plain MV3, ES modules, no build. `newtab.html` is the shell; each widget is a module in `widgets/` with one interface; pure logic (layout, dates, timer, calculator, cache, drag maths, settings import, every API parser) lives in `lib/` or the widget's `parse()` and is tested with `node --test` against fixtures. Data shows from storage first and refreshes in the background (stale-while-revalidate).

**Tech Stack:** Chrome Manifest V3, vanilla JS/CSS, Web Audio, `node --test` (Node 20+), headless Edge for screenshots.

**Spec:** `docs/superpowers/specs/2026-11-27-termtab-design.md` · **Visual reference:** `docs/mockup/terminal-newtab.html` (the mockup wins on looks, the spec on behavior and data).

## Global Constraints

- MV3, `chrome_url_overrides.newtab = "newtab.html"`. Permissions exactly `storage`, `alarms`, `system.cpu`, `system.memory`. No `host_permissions`, no `notifications`, no remote code.
- Data sources (all verified to send `Access-Control-Allow-Origin`): `api.open-meteo.com/v1/forecast`, `geocoding-api.open-meteo.com/v1/search`, `hacker-news.firebaseio.com/v0`, `api.frankfurter.dev/v1`, `api.coingecko.com/api/v3`, `api.wikimedia.org/feed/v1/wikipedia/<lang>/onthisday/events/<MM>/<DD>`, `dev.to/api/articles`, `api.github.com/search/repositories`. Favicons as images from `https://www.google.com/s2/favicons?domain=<host>&sz=32`.
- The page renders from storage before any network request finishes. No background polling; fetches happen only while a new tab is open.
- Colors: window `#1e1e1e`, title bar `#383838 → #2e2e2e`, text `#d4d4d4`, dim `#8a8a8a`, traffic lights `#ff5f57` `#febc2e` `#28c840`, accents yellow `#e5c07b` blue `#61afef` green `#98c379` red `#e06c75` purple `#c678dd` cyan `#56b6c2`. Window radius 10 px; menu bar 28 px, translucent with blur.
- Fonts: content `"SF Mono", Menlo, Monaco, "JetBrains Mono", "Cascadia Code", Consolas, "D2Coding", monospace`; menu and title bars use the system UI font. No runtime web-font downloads.
- Prompt line on every widget: `<user>@<machine> ~ % <command>`, defaults `you` / `MacBook`.
- Everything free: no paid tier, no locked features.
- English and Korean via `chrome.i18n`, following the browser language. No user-facing string hard-coded in JS/HTML.
- Commits straight to `main`, one per task, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. No push or GitHub repo without the owner's go-ahead.

## Review Focus

1. Offline, an API down or rate-limited when a new tab opens → the page still renders everything from storage; only that widget's status line says `fetch failed · retry`. Pinned in Task 3 (`cache keeps the old value when the fetch fails`) and Task 7 (each `parse` rejects malformed JSON with an Error the widget catches).
2. Ten new tabs opened at once → one network request per data source, not ten. Pinned in Task 3 (`concurrent gets share one fetch`).
3. Midnight and week boundaries: a timer running across midnight, today's focus line, habits on Sunday→Monday (weeks start Monday). Pinned in Task 2 (`tick resets doneToday on a new day`, `weekDays is Monday-first across a month boundary`) and Task 5 (focus line clears when the stored day differs).
4. Importing a broken, foreign or older settings file → rejected with a message, current settings untouched. Pinned in Task 8 (`importSettings rejects bad JSON, wrong app, newer version`).
5. Calculator fed `1/0`, `2^^3`, `alert(1)`, a 500-char string → an error line, never a crash and never `eval`. Pinned in Task 2 (`evaluate` tests).

### Task 3: Stale-while-revalidate cache

**Files:**
- Create: `lib/cache.js`, `test/cache.test.js`

**Interfaces:**
- Consumes: `createStore` (Task 1); a session store with the same shape for locks.
- Produces: `createCache({ store, session, now = Date.now }) → { get(key, ttlMs, fetcher, onUpdate) → Promise<{ value, fetchedAt, error: boolean } | null> }`. Returns the stored entry at once (or `null`). If missing or older than `ttlMs` and no lock `lock:<key>` younger than 30 s exists, sets the lock, awaits `fetcher()`, stores `{ value, fetchedAt }`, clears the lock and calls `onUpdate(entry)`. On fetch failure stores `{ ...old, error: true }`, clears the lock and calls `onUpdate`.

- [ ] **Step 1: Failing tests:** fresh entry → fetcher not called; stale entry → old value returned first, fetcher called once, `onUpdate` gets the new value; **`cache keeps the old value when the fetch fails`** (value unchanged, `error: true`); **`concurrent gets share one fetch`** (two `get`s in the same tick with a slow fetcher → fetcher called once); a lock older than 30 s is ignored (crashed tab).
- [ ] **Step 2:** `npm test` — FAIL. **Step 3:** implement. **Step 4:** PASS.
- [ ] **Step 5:** Commit `feat: stale-while-revalidate cache with a fetch lock`.
